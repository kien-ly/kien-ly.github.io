# System Design: Learning Path

Read in order, then practise with the [system design problems](/interview-prep/practice/system-design/).

| # | Module | You will be able to |
|---|---|---|
| 1 | [Interview framework](/interview-prep/learn/system-design/01-interview-framework/) | Run a structured 45-minute design interview and show senior signals |
| 2 | [Back-of-envelope estimation](/interview-prep/learn/system-design/02-back-of-envelope/) | Turn volumes into partitions, storage, compute and cost |
| 3 | [Building blocks](/interview-prep/learn/system-design/03-building-blocks/) | Pick and justify Kafka, stream engines, storage, serving stores, sketches |
| 4 | [Reliability patterns](/interview-prep/learn/system-design/04-reliability-patterns/) | Design idempotent, replayable, observable pipelines |
| 5 | [Hot keys across all systems](/interview-prep/learn/system-design/05-hot-keys/) | Detect and fix hot keys in Kafka, Spark, Flink, databases, caches and APIs, and explain the trade-off of each fix |
| 6 | [Data system design patterns](/interview-prep/learn/system-design/06-data-design-patterns/) | Use 25 named patterns (outbox, CDC, CQRS, event sourcing, sagas, WAP, claim check, sketches, bulkheads…) and state their trade-offs |
| - | [Quick reference](/interview-prep/learn/system-design/quick-reference/) · [Printable cheatsheet](/interview-prep/learn/system-design/quick-reference/) | Revise the day before |

Then go deeper on architecture topics in [learn/architecture](/interview-prep/learn/architecture/).
